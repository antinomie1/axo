# Axo engineering rules

- Performance is the first priority. Hot paths must remain zero-allocation (VT parsing, PTY read loops, render instancing). Idle CPU must be strictly 0% (no polling, no permanent tickers; repaints are paced by compositor frame callbacks and merged via atomic dirty flags). Always measure and record concrete throughput (MiB/s) and latency metrics for consequential changes.
- Reject overengineering and keep the codebase lean. Avoid speculative abstractions, unnecessary trait layers, forwarding-only crates, or heavy external dependencies (no async runtimes, no serde). Solve concrete problems with direct, minimal data structures and functions. Keep binary size small (~2.4 MiB release) and startup instantaneous.
- Maximize reuse across aegle and Axo. Thoroughly leverage aegle's existing infrastructure: shared Vulkan device and graphics queue (`App::vulkan()`), text shaping and fallback (`aegle-text`), glyph rasterization cache (`aegle-glyph`), UI markup (`.aegle`), and platform window/IME backends (`aegle-platform-sdl3`). Internally, unify shared domain models (e.g. Kitty and Sixel share the placement model and history eviction ring; primary and alternate screens share grid primitives).
- Keep tests in each crate's `tests/` directory, outside `src/`. Test actual protocol parsing, escape sequences, PTY interactions, IME transactions, and rendering boundaries. Prefer integrated scenarios with diffable assertions over tests mirroring every private method. Run `cargo test --workspace` and `cargo clippy --workspace --all-targets -- -D warnings` before completing any task.
- Validate inputs and FFI invariants once at their boundaries. Internal code relies on established invariants; avoid redundant defensive checks, silent fallbacks, or speculative scaffolding.
- Keep documentation lean and factual. Treat `README.md` and `TODO.md` as live, concise design references. Never keep obsolete notes, defensive boilerplate, or unverified claims.
